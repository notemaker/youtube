# 影音收集庫｜產品規格書

> 版本：0.1（第一階段）  
> 更新日期：2026-10-27  
> 產品定位：以 Google 試算表作為資料來源，透過 Google Apps Script Web App 讀寫影音收藏的跨裝置管理工具。

## 1. 產品目標

讓使用者能在桌機、筆電、平板與手機上，快速收集、整理、搜尋與開啟影音內容。第一階段以「可落地的收藏清單」為核心：前端提供清楚的瀏覽與編輯體驗，Google 試算表保存資料，Apps Script Web App 作為簡單、可維護的 API 橋接層。

## 2. 使用情境

1. 使用者看到 YouTube、Vimeo、Podcast 或其他影音來源時，新增一筆收藏，記下標題、連結、分類與標籤。
2. 使用者在收藏清單以關鍵字找片，或依類型、分類、觀看狀態、評分與最近更新排序。
3. 使用者在手機上快速把項目標記為「已完成」，在桌機上補充備註與評分。
4. 使用者開啟詳情面板，查看縮圖、來源連結、標籤、備註與時間欄位，再編輯或刪除。
5. 管理者可在 Google 試算表維護分類、標籤與狀態選項，並透過 Apps Script 部署設定讓前端連線。

## 3. 第一階段範圍

### 必要功能

- 收藏清單：卡片式瀏覽，顯示縮圖、標題、類型、分類、觀看狀態、評分與更新時間。
- 新增、檢視、編輯、刪除收藏。
- 搜尋：依標題、來源、分類、標籤與備註做關鍵字比對。
- 篩選：影音類型、分類、觀看狀態、標籤、最低評分。
- 排序：最近更新、最近加入、評分高低、標題字母序。
- 狀態：待觀看、觀看中、已完成、封存。
- 詳情面板：集中呈現收藏資訊與操作。
- Google Apps Script Web App 設定：前端可輸入 API URL，並保留示範資料模式供預覽。
- 明確的載入中、空白、無結果、成功與錯誤回饋。
- 響應式導覽與排版：桌機／筆電雙欄、平板彈性雙欄、手機單欄與底部操作列。

### 第一階段不包含

- 影音檔案上傳與串流播放。
- 自動抓取第三方網站 metadata、OAuth 登入、多人協作權限。
- 複雜的播放進度同步、通知與離線同步。

## 4. 資訊架構與頁面

- `/` 收藏總覽：統計摘要、搜尋、篩選、排序、收藏卡片。
- 詳情面板（同頁抽屜）：完整資訊、來源連結、編輯／刪除、狀態快速更新。
- 新增／編輯面板（同頁抽屜）：欄位表單與必要欄位驗證。
- 設定頁（同頁視圖）：Apps Script Web App URL、連線狀態、資料表結構與部署指引。

## 5. 資料模型

### 5.1 `Media` 工作表

| 欄位 | 型別 | 必填 | 說明 |
| --- | --- | --- | --- |
| id | string | 是 | UUID 或 Apps Script 產生的唯一識別碼 |
| title | string | 是 | 影音標題 |
| mediaType | enum | 是 | 影片、Podcast、音樂、直播、文章／其他 |
| sourceUrl | string | 是 | 原始來源連結，需為合法 http(s) URL |
| thumbnailUrl | string | 否 | 縮圖 URL；空值時前端顯示預設圖 |
| category | string | 否 | 主要分類 |
| tags | string | 否 | 以逗號分隔，前端轉為標籤陣列 |
| status | enum | 是 | 待觀看、觀看中、已完成、封存 |
| rating | number | 否 | 0–5，可用 0.5 間隔 |
| notes | string | 否 | 個人備註 |
| createdAt | ISO string | 是 | 建立時間 |
| updatedAt | ISO string | 是 | 最後更新時間 |

### 5.2 `Lists` 工作表

| 欄位 | 說明 |
| --- | --- |
| kind | `category` 或 `tag` |
| value | 選項文字 |
| color | 選用的顏色 token |
| sortOrder | 顯示順序 |
| active | TRUE／FALSE |

### 5.3 建議試算表設定

- 第一列固定為欄位名稱，不要合併儲存格。
- `Media` 與 `Lists` 分開工作表；第一階段前端可先以內建選項運作。
- Apps Script 透過 `SpreadsheetApp.openById(SPREADSHEET_ID)` 存取資料。
- API URL 不等於試算表 ID；前端只保存部署後的 Web App URL，試算表 ID 留在 Apps Script Script Properties。

## 6. API 契約（Apps Script Web App）

### 6.1 請求格式

`GET` 用 query string；`POST` 用 JSON body。建議所有回應都使用：

```json
{
  "ok": true,
  "data": {},
  "error": null,
  "meta": { "requestId": "...", "version": "0.2", "httpStatus": 200 }
}
```

### 6.2 動作

- `GET ?action=list`：回傳 `Media[]`，支援 `q`、`status`、`mediaType`、`category`、`sort`。
- `POST {"action":"create","item":{...}}`：新增收藏，服務端補上 `id`、`createdAt`、`updatedAt`。
- `POST {"action":"update","id":"...","item":{...}}`：更新允許欄位與 `updatedAt`。
- `POST {"action":"delete","id":"..."}`：刪除收藏。
- `GET ?action=meta`：回傳分類、標籤、狀態與 API 版本。

### 6.3 錯誤處理

- `400`：缺少 action、必要欄位、URL 不合法或資料格式錯誤。
- `404`：找不到指定 id。
- `409`：更新時版本或資料衝突（可選）。
- `500`：試算表或 Apps Script 例外。
- 前端不得只顯示 HTTP code，需顯示可理解的繁體中文訊息，並保留「重試」操作。
- Apps Script Web App 的 `ContentService` 以 JSON `meta.httpStatus` 傳遞狀態語意；若日後加上可控制 HTTP header／status 的同源代理，再將此欄位映射為實際 HTTP 狀態碼。前端不得依賴瀏覽器只讀 HTTP status。
- 若前端與 Apps Script 部署於不同來源，正式環境需驗證瀏覽器跨來源讀寫；若受 CORS／重導限制，改以同源 server proxy 或 Google Apps Script 的 JSONP（僅限 GET）策略處理，不在本版示範資料模式中假設已完成。

## 7. 操作流程

### 新增

點擊「新增收藏」→ 填寫標題／來源連結／類型／狀態 → 前端驗證 → 呼叫 `create` → 顯示成功 toast → 關閉面板並更新清單。

### 編輯與狀態更新

從卡片或詳情面板點擊編輯 → 預填資料 → 送出 `update` → 保留清單篩選條件 → 更新卡片並顯示成功訊息。狀態按鈕可提供快速更新，但仍需寫回試算表。

### 刪除

從詳情面板點擊刪除 → 顯示不可誤觸的確認訊息 → 呼叫 `delete` → 成功後移除卡片；失敗則保留原資料並顯示重試。

## 8. 響應式設計

- 桌機／筆電（≥ 1100px）：左側固定導覽 240px、內容最大寬度 1280px，收藏卡片 3 欄。
- 平板（768–1099px）：縮小側欄或改為頂部導覽，收藏卡片 2 欄，詳情面板寬度 420px。
- 手機（< 768px）：單欄卡片，篩選改為可展開工具列，新增按鈕固定於右下，詳情與表單改為全螢幕面板。
- 互動元件最小點擊區域約 44px；避免只靠 hover 傳達資訊；焦點狀態清楚可見。

## 9. 視覺與互動設計

採「編輯室索引卡」與「夜間放映」融合的介面語言：深墨綠背景承托米白內容卡，使用偏橘的「播放指示燈」作為品牌色。主要原則是高資訊密度但不擁擠、以縮圖與狀態做快速掃讀、以抽屜保留上下文、所有動作都有即時回饋。標題使用具人文感的襯線字，介面文字使用清晰的無襯線字，建立「收藏檔案館」而不是一般 SaaS 儀表板的感覺。

- 核心色彩：墨綠 `#102522`、米白 `#F5F0E8`、播放橘 `#FF7A45`、鼠尾草 `#B8D8C8`、深灰 `#283735`。
- 字體：標題 `Noto Serif TC`，介面 `Noto Sans TC`，以系統 fallback 確保載入失敗仍可讀。
- 動畫：面板 180–240ms 滑入；卡片 hover 僅提升陰影與縮圖亮度；成功回饋使用短暫淡入，不使用會干擾閱讀的連續動畫。
- 品牌語氣：「把想看的，留在看得見的地方。」、「先收進來，等有空再看。」

## 10. 驗收標準

1. 能在桌機、筆電、平板與手機寬度下正常瀏覽，沒有水平溢出，導航與主要操作可使用。
2. 首頁能顯示統計摘要、搜尋列、篩選列與收藏卡片；卡片能開啟來源連結。
3. 新增／編輯表單會驗證標題、來源 URL、類型與狀態，並對成功／失敗提供清楚回饋。
4. 詳情面板能集中顯示縮圖、關鍵資訊、標籤、備註與操作。
5. 搜尋、篩選與排序能即時影響清單，無結果時顯示明確空狀態。
6. 預設示範資料可離線預覽；設定頁能切換 Apps Script API URL 與資料來源模式。
7. 規格中定義的 `Media`／`Lists` 欄位與 API 契約可直接交給 Apps Script 實作。
8. 所有讀寫操作都保留載入、成功與錯誤狀態，不會讓使用者無法判斷是否完成。

## 11. 後續迭代

- Apps Script 真實端點與部署自動檢查。
- 多使用者登入與每人收藏分區。
- YouTube／Podcast metadata 自動補齊。
- 收藏匯入／匯出 CSV、批次編輯與播放進度。
- PWA 安裝、離線快取與行動裝置分享至收藏。
